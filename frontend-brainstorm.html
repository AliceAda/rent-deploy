一、影响 × 成本 优先级矩阵

纵轴=业务/体验影响，横轴=实施成本。优先摘「高影响·低成本」象限，再排期「高影响·高成本」战略项。

速赢（先做） 战略大项（排期） 填充项（有余力做） 高成本低回报（谨慎）

二、分主题创意清单

每条标注优先级 高中低，可据此裁剪范围。

流量 / SEO

面向公众的获客能力

  • 高hash→history 模式 + 服务端渲染/静态生成，让房源页可被搜索引擎收录（当前 hash 路由对 SEO 不友好，DEPLOY.md 已自陈）。
  • 中每套房源注入 schema.org/Residence 结构化数据 + 动态 meta/OG 标签，提升搜索摘要与分享卡片质量。
  • 中站点地图(sitemap)、robots、城市/商圈聚合落地页（/city/beijing 等）做 SEO 长尾。
  • 低SSR 首屏骨架 + 预取下一页，兼顾收录与体验。
移动优先

租房是手机场景

  • 高Element Plus 偏桌面，需补移动端响应式/移动端独立布局：底部 Tab 栏、抽屉筛选、手势返回。
  • 高首页与找房页做移动端重排：地图入口、卡片流、下拉刷新、无限滚动。
  • 中引入 viewport 单位与 clamp() 流式排版，统一多端间距体系。
  • 低微信/小程序同构（如需）可考虑 Taro/uni-app 复用逻辑层。
找房核心体验

地图 · 对比 · 富媒体

  • 高地图找房：高德/腾讯地图标点、圈选范围、周边配套（地铁/商超/学校）与通勤时间。
  • 中房源详情富媒体：图片画廊、视频、VR 看房，替代当前纯图文。
  • 中智能筛选升级：价格/户型/通勤等多维条件 + 保存筛选方案。
  • 低Compare.vue 现有对比加雷达图（性价比/交通/配套维度），ECharts 已就绪。
AI / 智能化

把 ChatWidget 用起来

  • 中深化 ChatWidget.vue：房东-租客 IM、自动问答（FAQ 机器人）、转人工工单。
  • 中AI 生成房源描述/标题，降低房东发布门槛（PublishHouse.vue 接入）。
  • 低租金估价可视化：用 ECharts 画小区历史租金曲线，辅助定价。
  • 低基于浏览历史的「猜你喜欢」推荐位（Home.vue）。
性能 / 工程

体量与可维护性

  • 高Element Plus 按需引入（unplugin-auto-import + components），替换 `app.use(ElementPlus)` 全量，首包显著下降。
  • 中长列表（房源/工单/消息）改虚拟滚动，降低 DOM 与卡顿。
  • 中图片懒加载 + WebP/AVIF + CDN；首屏骨架屏与路由级预取。
  • 低Bundle 分析（rollup-plugin-visualizer），按路由更细分包。
设计 / 品牌

统一与质感

  • 中建立 Design Tokens（颜色/间距/圆角/阴影 CSS 变量），统一三门户视觉。
  • 中深色模式（DEPLOY.md 已预告），用 CSS 变量主题切换。
  • 中微交互与过渡动效体系，提升高级感。
  • 低无障碍(a11y)：键盘导航、ARIA、对比度合规。
质量 / 协作

从原型到产品

  • 中补齐测试：当前仅 composables 有 vitest，补组件/接口契约测试（MSW 天然适配）。
  • 中Storybook 沉淀 HouseCard 等为基础组件库，支撑多门户复用。
  • 中TypeScript 严格化（strict）、E2E（Playwright）核心链路。
  • 低CI：type-check + test + build + 预览部署门禁。
架构演进

规模化准备

  • 中i18n 国际化（DEPLOY.md 已预告），vue-i18n + 文案集中。
  • 中Pinia 状态持久化 + 按域拆分 store，减少刷新丢失。
  • 低微前端拆分 user/landlord/admin（成本高，仅超大团队需要，谨慎）。
  • 低设计稿到代码：Figma 变量联动。

三、建议优先落地的「速赢」清单

低成本、可在一两个迭代内见效，且不影响现有 mock/API 切换架构。

中租金趋势图复用 ECharts（已装）房东定价/租客决策有数据支撑
